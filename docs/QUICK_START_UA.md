# Solar Designer Lite — короткий старт

Це попередня версія 0.1 під ліцензією MPL-2.0. Зберігайте LICENSE, ATTRIBUTION.md та THIRD_PARTY_NOTICES.txt разом із програмою.

## Відкрити й пройти приклад

1. Розпакуйте весь ZIP в окрему папку. Відкрийте `Solar_Designer_Lite.html` подвійним натисканням у браузері. Node та інтернет для роботи не потрібні. Автоматизовано перевірено Chrome на macOS; інші браузери й ОС ще не перевірені.
2. Натисніть «Відкрити JSON» і виберіть `data/examples/trina435-manual24.json`. Перемикач EN/UA змінює мову. Student Mode додає навчальні пояснення; `student-50kw.json` — окремий синтетичний навчальний приклад.
3. У реальному прикладі вибрано Trina Solar TSM-435NEG9R.28 та SMA STP8.0-3AV-40. У «Стрінги та MPPT» є два ручні стрінги по 12 модулів на MPPT A/B: розміщено 24/24. Після редагування натисніть кнопку застосування ручного плану. Незастосована чернетка не потрапить до збереженого JSON; програма попросить спочатку її застосувати.
4. У «Перевірки» перегляньте окремі PASS, FAIL та UNKNOWN. Відомі cold-Voc перевірки прикладу проходять; βVmp та окремі physical-input ratings лишаються невідомими. Підсумок UNKNOWN означає неповну перевірку, а не підтвердження придатності до монтажу. Нуль автоматично розміщених модулів за відсутнього βVmp означає блокування генератора даними.
5. У панелі «Що потрібно уточнити» MISSING означає відсутнє значення, PROVIDED — уже задану залежність, REVIEW — потребу перевірити межі модуля або джерело. Розкрийте поле, щоб побачити одиниці, пов’язані перевірки й джерела. Посилання на datasheet саме по собі не доводить, що в ньому є відсутній параметр. Не заповнюйте його типовим значенням іншої моделі.
6. Збережіть переносний проєкт кнопкою «Зберегти JSON». У «Звіт і BOM» натисніть «Завантажити звіт» для Markdown або друк для PDF. Звіт/PDF не замінює JSON для відновлення проєкту. Автозбереження залежить від доступності сховища браузера; якщо з’явилося попередження, експортуйте JSON. Копію JSON варто зберігати незалежно від автозбереження.

## Межі та повідомлення про проблему

Це попередня електрична перевірка звичайних string inverters з одним типом обладнання в проєкті. Кабелі, захист, SPD та DC-роз’єднувач мають окремі непідтверджені монтажні/координаційні умови. Немає підтвердженої відповідності UA/CZ, підтримки паралельних кабелів чи оптимізаторів. Перед реальним монтажем потрібні первинні дані й незалежна інженерна перевірка.

«Про проєкт» показує походження й повідомлення про сторонні компоненти. Прихованого відстеження використання немає. Для повідомлення про проблему відкрийте Issue на GitHub і запишіть версію, ОС/браузер, кроки, очікувану й фактичну поведінку; за потреби додайте мінімальний JSON без приватних чи клієнтських даних.

`PACK_MANIFEST.json` містить версію, склад і розміри, `SHA256SUMS.txt` — контрольні суми файлів. Вони допомагають виявити пошкодження, але не підтверджують авторство, інженерну правильність чи право публічного поширення. Не редагуйте оригінальний комплект для перевірки сум; свої проєкти зберігайте окремо.
