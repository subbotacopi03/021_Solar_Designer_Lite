# Перед public release

1. Вибрати та додати повний текст ліцензії; підтвердити права на будь-який майбутній source reuse.
2. Перевірити exact manufacturer SKUs, datasheets, cable Iz і installation basis.
3. Затвердити проектні policy та джерела, окремо UA/CZ normative packs.
4. Завершити повний protection/SPD scope або чітко залишити preliminary release.
5. Перевірити heterogeneous topology, optimizer support та supported limits.
6. Зробити окремі package builds, exports/declarations і package-tarball smoke.
7. Налаштувати dependency audit, release versioning, issue templates та contributor review.
8. Пілотувати зі студентами й незалежним інженерним review.
9. Випустити changelog і документацію implemented-vs-planned.
10. Лише після цих рішень опублікувати GitHub/npm та відкрити доступ.
