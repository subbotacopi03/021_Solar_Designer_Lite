## 2. Виявлені та виправлені дефекти під час P1

1. **Відображення інвертора у вихідних даних огляду (Overview):**
   - *Дефект:* У блоці «Вихідні дані» розділу «Огляд» показувалася назва та потужність PV модуля, але для інвертора виводилося лише поле кількості (`inverter_quantity`), без зазначення обраної моделі та потужності.
   - *Виправлення:* Додано блок відображення інвертора (`project.inverter.name · ac_power_w kW`) поруч із модулем у сітці форми розділу «Огляд».

2. **Локалізація та обробка помилок редагування маршрутів (Routes):**
   - *Дефект:* Функція `bindRoutes` не отримувала поточну мову `lang`, через що повідомлення про нечислове значення або відсутність цілі виводилися англійською (`Invalid route value`, `String target is no longer available`), а помилки схеми виводилися необробленими рядками без форматування.
   - *Виправлення:* У `bindRoutes` передано параметр `lang`, підключено `formatInputError(reason, lang)` для зрозумілих повідомлень українською та англійською, а також локалізовано системні повідомлення.

3. **Локалізація ліміту розміру файлу JSON при завантаженні:**
   - *Дефект:* При виборі файлу понад 1 МіБ повідомлення `JSON size limit: 1 MiB` було жорстко закодоване англійською мовою.
   - *Виправлення:* Замінено на двомовне повідомлення залежно від обраної мови інтерфейсу.

4. **Повідомлення інспектора кабелів за відсутності кандидатів:**
   - *Дефект:* Коли в проєкті не було завантажено кабелі (`project.cables = []`), інспектор двічі підряд показував одне й те саме повідомлення `Немає доведеного кандидата кабелю для цієї лінії.` (у банері та в порожньому списку кандидатів).
   - *Виправлення:* Додано окреме пояснення `noCandidates`: «У проєкті не вибрано кабелів для цієї лінії. Оберіть набір даних у «Каталог кабелів» вище або задайте кабелі в JSON.»

5. **Фокус клавіатури на інтерактивних елементах `<summary>` та `<a>`:**
   - *Дефект:* У `style.css` правила `:focus-visible` були визначені для `button`, `input`, `textarea`, `select`, але не містили `summary` та `a`, через що фокус на розкривних панелях та посиланнях міг бути малопомітним.
   - *Виправлення:* Додано `summary:focus-visible, a:focus-visible` із контрастним контуром 3px `#2e5bff`.

## 3. Чеклист для власника (Human Pilot Checklist)

Цей чеклист підготовлено для перевірки власником або запрошеним тестером на власній машині без потреби в інструментах розробника (Node, Git, pnpm):

- [ ] **Крок 1. Запуск без інтернету:** Відкрити файл `Solar_Designer_Lite.html` у браузері подвійним кліком (відключити Wi-Fi за бажанням). Переконатися, що інтерфейс відкрився, немає запитів до зовнішніх CDN і показано стартове навчальне демо.
- [ ] **Крок 2. Імпорт реального проєкту:** Натиснути кнопку «Відкрити JSON» і обрати `data/examples/trina435-manual24.json`. Перевірити, що назва проєкту змінилася на `Trina 435 W / SMA 8 kW · manual 2 × 12 · preliminary checks`, а у блоці «Вихідні дані» видно модуль Trina та інвертор SMA.
- [ ] **Крок 3. Перегляд стрінгів:** Перейти у розділ «Стрінги та MPPT». Переконатися, що розміщено 24/24 модулів (по 12 на трекерах A та B).
- [ ] **Крок 4. Спроба редагування:** Змінити кількість модулів у першому стрінгу з 12 на 14. Спробувати перейти в інший розділ — з'явиться вікно підтвердження. Натиснути «Скасувати» і переконатися, що число 14 збереглося. Натиснути «Застосувати ручний план» — кількість розміщених модулів стане 26.
- [ ] **Крок 5. Збереження та перевірка файлу:** Натиснути «Зберегти JSON». Відкрити збережений файл у будь-якому текстовому редакторі й переконатися, що перший стрінг має `modules: 14`.
- [ ] **Крок 6. Перевірка невідомих даних:** Перейти у розділ «Перевірки». Переглянути панель «Що потрібно уточнити». Розкрити блок `Температурний коефіцієнт βVmp` і натиснути «Перейти до даних» — переконатися, що відкрився розділ «Обладнання».
- [ ] **Крок 7. Експорт звіту:** Перейти у розділ «Звіт і BOM». Натиснути «Завантажити звіт» (Markdown) та «Друк / PDF». Перевірити, що у звіті вказано фактичне обладнання та статус UNKNOWN.
