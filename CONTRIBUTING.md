# Як зробити внесок

Дякуємо за допомогу. Проєкт розвивається спільно з інженерами-проєктувальниками, тому найцінніше — перевірені дані й чесні розрахунки.

## Повідомити про проблему

Відкрийте [Issue](https://github.com/subbotacopi03/021_Solar_Designer_Lite/issues/new/choose) і виберіть шаблон: помилка програми, розбіжність з ручним розрахунком або дані обладнання. Додайте мінімальний project JSON без адрес, клієнтів, цін і тарифів.

## Що приймається

1. Запис обладнання: точний SKU, офіційний datasheet виробника (URL, редакція, дата), одиниці, температурні коефіцієнти зі знаком, межі MPPT і фізичних входів. Невідоме поле лишається `null`. Без цін.
2. Тест: незалежний ручний розрахунок з формулою й допуском, порівняний з результатом програми. Старий результат програми сам по собі не є доказом.
3. Приклад: синтетичний проєкт без адрес, клієнтів, облікових даних і тарифів.
4. Переклад: українська та англійська, без зміни позначень SI та ідентифікаторів перевірок.
5. Зміна формули: специфікація `docs/spec/electrical-v0.1.md` → тест з ручною арифметикою → код → свідоме оновлення `docs/spec/formula-manifest.json`. Не оновлюйте хеш, щоб приховати неперевірену формулу.

## Правила розрахунків

- Відсутні дані дають UNKNOWN; жодних «типових» значень.
- Відомий FAIL не приховується відсутністю інших даних.
- Voc/Vmp, Isc/Imp, межі MPPT і фізичних входів, max series fuse і reverse-current withstand перевіряються окремо.
- Ядро `packages/core` чисте: без файлів, мережі, цін і клієнтських даних.
- Економіка, тарифи, ціни, CAD/GIS поза межами проєкту.

## Pull request

Перед PR запустіть `pnpm check`. Опишіть поведінку, як перевіряли та обмеження. Хороші перші задачі: запис модуля чи інвертора, регресійний тест, переклад, виправлення документації, звіт про роботу в Windows/Firefox/Safari.
